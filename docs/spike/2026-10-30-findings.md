## Q9. Recipe chung (spike 2, 2026-10-31): mọi kiến trúc thay cho bảng model family

Nhân muốn `qtool quantize` nhận mọi model. Script spike `quantize_generic.py` (bỏ đi) suy recipe từ `config.json`
+ cấu trúc module, không tra bảng theo tên. Thử trên Qwen3.5-4B (đối chiếu) + 3 model không gated
(Llama 3.2 / Gemma 3 bị gated, rtx4070 không có `HF_TOKEN`).

Quy tắc đã chạy đúng:

| Mục | Quy tắc |
|---|---|
| Load | có `vision_config` → `AutoModelForImageTextToText`, còn lại `AutoModelForCausalLM` (không `trust_remote_code`) |
| MoE | `llmcompressor.modeling.moe.linearize.linearize_moe(model)` **trước khi** suy ignore: transformers v5 gộp expert thành tensor 3D (`OlmoeExperts`), chỉ còn 65 `Linear` (attention + lm_head); sau linearize: 3,136. `oneshot` cũng tự linearize nhưng khi đó ignore list đã suy sai. `moe_calibrate_all_experts` mặc định bật |
| Ignore | luôn `re:.*lm_head`; tên module bắt đầu bằng `visual`, `vision_tower`, `vision_model`, `vision_encoder`, `multi_modal_projector`, `mm_projector`, `connector` → `re:.*<tên>.*`; MoE: `Linear` có `out_features` ∈ {số expert, 1}; hybrid (`layer_types` có loại khác attention): `linear_attn` / `mamba` / `mixer` / `ssm` |
| Layer tuần tự | `ModuleList` không thuộc vision, lớn nhất, **có class nằm trong `_no_split_modules`** (chọn theo kích thước thuần → chọn nhầm danh sách 64 expert của OLMoE) |

Lỗi gặp (đều là bài học cho tool):

1. **Chat template làm rơi nội dung, không báo lỗi**: SmolVLM `apply_chat_template` với `content` chuỗi →
   `'<|im_start|>User: <end_of_utterance>\nAssistant: <end_of_utterance>\n'`. Lượt đầu calib trung vị **34 token** (đúng ra ~1,100).
   lm_eval chế độ chat cũng truyền chuỗi → prompt rỗng → phải eval SmolVLM2 ở chế độ completion.
2. **Processor đa phương thức cần gói phụ**: `ImportError: Package num2words is required to run SmolVLM processor` — ở `oneshot`
   (tự khởi tạo processor khi có dataset; tránh bằng `processor=tok`) **và ở vLLM** (fixture `eval-smolvlm2-bf16.err-num2words.log`).
   Spike thêm `num2words` vào image eval (`qtool-eval:spike` = `spike-base` + `pip install num2words`).
3. **Baseline BF16 không vừa GPU dù bản quantize vừa**: OLMoE 12.89 GiB weight, `gpu_memory_utilization=0.85` →
   `ValueError: No available memory for the cache blocks` (fixture `eval-olmoe-bf16.err-no-kv-memory.log`).
   Chạy được ở 0.95 (KV 5,360 token, concurrency 1.31×).
4. **Dòng log vLLM đổi file theo model**: `[model_runner.py:380] Model loading took ...` (Phi-4-mini, SmolVLM2)
   vs `[gpu_model_runner.py:5515]` (Qwen3.5, OLMoE) → regex bám nội dung, không bám `[file:line]`.
5. Spike chạy song song nhầm 2 batch (lệnh bị từ chối vẫn chạy trên remote) → trùng tên container `qtool-spike`, log bị ghi đè.
   Tool: tên container `qtool-<pid>` + lock file (đã có trong spec) là đúng.

## Ảnh hưởng tới spec

1. **§5 Kiến trúc — image compress có 2 biến thể** `cu129` (SM 7.5–12.0) và `cu126` (SM 5.0–9.0, có V100); tool chọn theo SM
   (SM 7.5–9.0 dùng được cả hai → mặc định cu129). Base `python:3.11-slim` + `gcc libc6-dev`, torch 2.13.0, llmcompressor 0.13.0,
   transformers 5.14.1.
2. **§5 Image eval**: cài lm-eval 0.4.13 với constraint `torch|vllm|transformers|compressed-tensors` của image vLLM + `huggingface-hub<2.0`.
3. **§3 Recipe Qwen3.5**: load `Qwen3_5ForConditionalGeneration`; ignore `re:.*lm_head`, `re:.*embed_tokens$`, `re:.*visual.*`,
   `re:.*model.visual.*`, `re:.*linear_attn.*`; `oneshot(..., sequential_targets=["Qwen3_5DecoderLayer"])`;
   lưu MTP bằng `save_mtp_tensors_to_checkpoint` tường minh. SmoothQuant tự suy mapping — không cần mapping tay.
   → Recipe phụ thuộc kiến trúc: spec cần mục "model family" (bản đầu: Qwen3.5) hoặc quy tắc chung đọc từ config.
4. **§3 / §8 Eval**: chế độ **chat** (`--apply_chat_template --fewshot_as_multiturn`, `enable_thinking=False`) thay cho chế độ docs
   (completion) — lệch khỏi docs vLLM, điểm BF16 0.82 vs 0.70. Không truyền `add_bos_token`.
   Model args bắt buộc cho hybrid: `max_num_seqs` (64), `max_model_len` (4096), `gpu_memory_utilization` (0.85).
5. **§3 bảng scheme**: `int4-w4a8-int8` bỏ nhãn experimental trên SM 8.9 (chạy được, 0.80).
6. **§7A Preflight**: kiểm **RAM host** ngoài VRAM. BF16: VRAM ≥ 0.6 × size, RAM ≥ 1.4 × size. FP32 (SM < 8.0): VRAM ≥ 1.0 × size,
   RAM ≥ 3.5 × size (4B: +28.6 GB đo được). Container quantize chạy với `--memory` để không làm sập host.
7. **§6 / §8 thời gian**: khởi tạo vLLM ~4.5 phút mỗi lượt eval; quantize 4B ~15 phút (W4A16) / ~25 phút (W8A8) trên 4070;
   9B W4A16 ~22 phút; V100 FP32 ~10 lần chậm hơn → log nên in ETA từ tqdm.
8. **§5 Parse**: dòng kernel vLLM có 2 dạng (`Using X for Y`, `Selected X for Y`); dtype model đọc ở `text_config.dtype` khi
   cấp trên cùng không có; nvidia-smi không cho tên container (map PID → container nếu muốn in).
9. **§5 quantize.py / runner**: compute FP32 → cast về dtype gốc trước khi lưu (không thì checkpoint FP32, to gần gấp đôi);
   container chạy `--user $(id -u):$(id -g)` để file checkpoint thuộc user (spike: root + mode 600).
10. **Ngoài phạm vi, ghi nhận**: cài `flash-linear-attention` có thể tăng tốc calib lớp GDN (chưa thử).
11. **§2 / §3 Model family → recipe chung** (Q9): bỏ bảng model family; suy recipe theo quy tắc Q9. Kiến trúc đã kiểm chứng:
    Qwen3.5, Phi3, OLMoE, SmolVLM (Llama text). Kiến trúc khác: nhãn `[unverified architecture]` + in ignore list / layer tuần tự
    suy ra; `--ignore` để dev thêm; `--no-eval` với kiến trúc chưa kiểm chứng → cảnh báo.
12. **§6 Eval mode tự chọn**: kiểm chat template (như calib); rơi nội dung → chế độ completion, in lý do. Không có template → completion.
13. **§7A Preflight eval**: weight baseline BF16 (và checkpoint) phải vừa `gpu_memory_utilization × VRAM` trừ dư cho KV / CUDA graph;
    không vừa → bỏ baseline kèm lý do (Δ / recovery `n/a`), không để vLLM lỗi giữa chừng. Cân nhắc nâng util lên 0.90–0.95 khi chỉ thiếu ít.
14. **§5 Image eval**: thêm gói phụ hay gặp của processor đa phương thức (`num2words`); lỗi `ImportError` khác → trích nguyên văn + gợi ý.
15. **§5 Parse**: regex dòng vLLM không phụ thuộc `[file:line]`.
16. **§6 Thời gian**: MoE quantize chậm hơn dense nhiều (OLMoE 7B 50 phút); RAM hệ số 1.0–1.6× size.
